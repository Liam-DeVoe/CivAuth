Docs
CivAuth lets your site sign people in with their Minecraft account. CivAuth apps are plain OAuth applications. The relevant URLs are:
Authorization {{ issuer }}/oauth/authorize
Token {{ issuer }}/oauth/token
User {{ issuer }}/oauth/user
See below for details.
1. Register an app
First, register an app at OAuth apps.
2. Authorize a user with CivAuth
When you want a user to log in with CivAuth, redirect them to https://civauth.civwiki.org/oauth/authorize, with the following query parameters:
GET {{ issuer }}/oauth/authorize ?response_type=code &client_id=3f9a1c &redirect_uri=https%3A%2F%2Fexample.com%2Fcallback &state=8c1f0e
response_type Required. Must be code.
client_id Required. The client id of your app.
redirect_uri Required. Must be listed as a redirect URI on your app. The user will be redirected here after they authorize your app.
state Optional. If passed, sent unchanged in the redirect URI. Used to tie the callback to the request that started the login, for security.
code_challenge Optional. Used for security; see PKCE. If sent, also send code_challenge_method=S256.
For now, there is no scope parameter. Each app gets the user's Minecraft name and UUID.
Once the user approves your app, they are redirected to the url in redirect_uri, with a code:
https://example.com/callback?code=Qm9vbXNoYWthbGFrYQ&state=8c1f0e
{{ notice('If the user declines, the callback contains error and error_description instead. See RFC 6749 §4.1.2.1.', label="Note") }}
3. Exchange the code for a token
Once you have a code from CivAuth, exchange it for a token by sending a POST to https://civauth.civwiki.org/oauth/token:
curl -d grant_type=authorization_code \ -d client_id=3f9a1c \ -d client_secret=CLIENT_SECRET \ -d code=Qm9vbXNoYWthbGFrYQ \ -d redirect_uri=https://example.com/callback \ {{ issuer }}/oauth/token
grant_type Required. Must be authorization_code.
client_id Required. Your app's client id.
client_secret Required. Your app's secret.
code Required. The code from the callback.
redirect_uri Required. The same redirect URI from the authorization request.
code_verifier Optional. Required if you sent code_challenge.
A successful exchange returns:
{"access_token": "oJ3kZQ8vT2mXpL5wR9bYcH1nAeKdG7sUfV4jMqW0xEo", "token_type": "Bearer", "expires_in": {{ token_ttl * 86400 }}, "refresh_token": "Xp2vN7dKq4RtW9yBcL3mHf8sJa6ZgUe1oVi5TnPk0Cw"}
The access token lasts {{ token_ttl }} days. The refresh token lasts {{ refresh_ttl }} days.
4. Look up the user
Use the access token to look up the user:
curl -H 'Authorization: Bearer oJ3kZQ8vT2mXpL5wR9bYcH1nAeKdG7sUfV4jMqW0xEo' {{ issuer }}/oauth/user
{"uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5", "name": "Notch"}
This returns the UUID and name of the Minecraft account.
5. Refresh an access token
When an access token expires, you can refresh it using the refresh token. POST to https://civauth.civwiki.org/oauth/token:
curl -d grant_type=refresh_token \ -d client_id=3f9a1c \ -d client_secret=CLIENT_SECRET \ -d refresh_token=Xp2vN7dKq4RtW9yBcL3mHf8sJa6ZgUe1oVi5TnPk0Cw \ {{ issuer }}/oauth/token
The response is the same as in the initial token exchange.
